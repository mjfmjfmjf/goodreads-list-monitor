# EMRYS-2026-09-04-QC — quality check of the new Emrys CSV

## What
New partner file `~/Downloads/emrys_2026_09_04.csv` (~102 MB unpacked, renamed
from `mjf_books_240k_100+ ratings.csv`). Goodreads-style export of OUR corpus,
restricted to the higher-rated books (~240k). Header (18 cols, `genres` name
used twice): `id,title,author,author_id,ratings,avg_rating,published,pages,
series_pos,genres[DB-json,mostly blank],last_updated,tags,
requires_auth,is_bad,fail_count,work_id,genres[RANKED],n_ratings`.

## KEY FINDING — the ranked `genres` enrichment (col 16) + `n_ratings` (col 17) are UNRELIABLE
The enrichment is frequently the shelf profile of a DIFFERENT book / a colliding key.

### Evidence
- Same 20-shelf signature on unrelated books: one profile (the shelves of
  *B Clones* by Laurann Dohner: Sci Fi|147, Romance|132, Laurann Dohner|97,
  Erotica|87, Cyborg|86, …) is attached to ≥7 unrelated titles incl.
  23995249 *The Invention of Nature* (Humboldt bio), *Focus* (Daniel Goleman),
  *Bleach vol 17*, *French Milk*, *The Van* (Roddy Doyle), *Seraph of the End*.
- **2026/09/05 — confirmed the flaw is in the RAW CSV, not our load.** Direct
  grep of `~/Downloads/emrys_2026_09_04.csv` for the 23995249 row shows the bogus
  profile verbatim (`genres=Sci Fi|147;Romance|132;Laurann Dohner|97;Erotica|87;…`)
  and it CONTRADICTS that same row's own `tags` column (`history:1055, climate:14,
  climate-change:16`). The scratch table `emrys_09_04_tags` faithfully mirrors the
  file; our loader added nothing. Repro: count rows whose top-1 shelf is "Sci Fi"
  with a "Laurann Dohner" shelf → 10 work_ids incl. 23995249, 444396 (Shane),
  24034566 (Focus), 26679990 (Seraph of the End), 2121971 (Bleach vol 17),
  1567032 (French Milk), 42186 (The Van), 42170982, 87582994 (B Clones — the ONLY
  legitimate one), 47281155.
- Root cause theory for feeding back to Emrys: his enrich step reused one book's
  shelf scrape for many — a join/caching collision (several inputs resolved to the
  same wrong shelf/work page, a fallback default, or a cache key collision); it is
  NOT confined to genres (`n_ratings` repeats across different work_ids too).
- `12,811` distinct signatures appear on >1 book (~26,358 books affected).
- Same `n_ratings` (7895) on three books with DIFFERENT work_ids
  (12272748=17248231, 135724628=152472373, 23995249=43595986) → keyed to
  neither book nor work. Root-cause theory: scrape/join where several inputs
  resolved to the same wrong shelf page (fallback/redirect) or misaligned rows.
- Sanity vs live Goodreads: `/book/show/23995249` and
  `/work/shelves/43595986-...` show real top shelves non-fiction, science,
  history, biography, nature, environment, natural-history, biology, audiobook,
  travel… NONE of the file's Sci-Fi/Laurann-Dohner/Erotica profile appears.
  OUR DB tags for 23995249 match the live page almost exactly (see QC below).

## Recommendation
Do NOT import col 16/17 wholesale into the DB. Our own `books.tags` per-book
shelf counts are accurate; if richer per-book genre/shelf data is wanted, scrape
per-work `/work/shelves/<work_id>` pages ourselves (throttle-aware, this compounds
with AGENTS.md politeness rules). The core cols 0–15 of this file basically match
the DB (as expected — it is our own corpus) with known drift on `ratings`/
`last_updated`.

## VERIFIED CROSS-CHECK (2026/09/04, 257,049 rows, point lookups on books.id)
- Presence: **257,049 / 257,049 present in DB — 0 missing** (matches expectation).
- `ratings`: 101,143 rows differ, all by ±1–5 (mostly DB higher; snapshot-vs-live
  staleness, no conflicts).
- `work_id`: of the 200,448 file rows that carry one, **200,448 EQUAL the DB's, 0
  differ**; 13,988 are DB-only (file lacks wid), 42,613 neither. File's `work_id`
  is trustworthy where present; DB is strictly more complete. (Earlier "78%
  mismatch" was a false alarm.)
- FOOTGUN discovered: `books.id` / `books.work_id` are TEXT columns; binding a
  JS **number** (e.g. an INTEGER column pulled from a scratch table) into
  `WHERE id=?` silently returns no row. Always coerce to `String(id)` before
  binding.
